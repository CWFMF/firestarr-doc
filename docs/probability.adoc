Determine rate of spread from probability of spread threshold.

[cols="1,2"]
|===
|Parameters |threshold	(Probability of spread threshold)
|Returns |Rate of spread at given threshold (m/min)
|===

Probability of spread is converted into the ROS that would give it, and then when checked the fire burns if ROS > ROS_threshold

`ROS = 25.0 / 4.0 * log(-(exp(41.0 / 25.0) * threshold) / (threshold - 1));`

Should be the inverse of: 

`P = 1 / (1 + exp(1.64 - 0.16 * ros));``

Where P is the threshold above.

==== In Practice

The spread potential thresholds are set using 3 separate random numbers, scenario, day and hour. These numbers are all drawn independently and aggregated into a total weight after being multiple against their weights as established with the THRESHOLD_***_WEIGHT.

What this looks like in practice is as follows.

Wherever the weighted simulation + daily + total threshold is above the value required for spread then the fire will spread. With the same scenario for weather, there can still be different outcomes. For example, if the scenario produced the sine-wave for the rate of spread, you can see that for the 2nd scenarios 1st day, the rate of spread is above the threshold most of the time, and thus it would spread, whereas the 1st scenario would spread briefly before noon, but otherwise not spread during that day.

Think of it like hourly burning conditions. The fire is only allowed to spread when the rate of spread at the pixel exceeds the threshold for that hour. By running many simulations with these thresholds being selceted randomly, you can get a sense of the likelihood of spread for a given scenario within a given timeframe.
